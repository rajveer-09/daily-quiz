1. What it is, and why it matters

  • Time complexity is how the number of operations grows with the input size n.
  • Space complexity is how much extra memory the algorithm needs as n grows.

Two programs can give the same answer, but one finishes in a blink and the other takes hours. Online judges give a time limit, usually 1–2 seconds, and a memory limit, usually 256 MB.

Rule of thumb: a computer does about 10^8 simple operations per second. Estimate your program's operations for the largest input and compare.

2. Counting steps

We don't time programs with a stopwatch. We count how the number of steps grows with the input size n.

long long sum = 0;
for (int i = 1; i <= n; i++) {   // runs n times
    sum += i;                    // 1 step each time
}
// about n steps in total

If n doubles, this loop does twice the work. That is linear growth, written O(n).

3. Big-O notation

Big-O describes how the running time grows for large n. To find it:

  1. Count the steps as a formula, e.g. 3n² + 5n + 7.
  2. Keep only the fastest-growing term: 3n².
  3. Drop the constant in front: n². So the code is O(n²).

For large n, the biggest term decides everything: at n = 10^5, n² is 10^10 while 5n is only 5 × 10^5.

  • The base of the log doesn't matter: log₃ n = log₂ n / log₂ 3, which is a constant times log₂ n. All are O(log n).
  • A big fixed number is still O(1). What matters is whether the count grows with n.
  • Check whether the inner loop variable resets. If j is set once outside both loops, it only moves from 0 to n once in total, so nested-looking code can be O(n):
int j = 0;                        // set once, never reset
for (int i = 0; i < n; i++)
    while (j < n) j++;            // all rounds together: j goes 0 to n once, so O(n), not O(n²)
#include <iostream>
using namespace std;

int main() {
    long long n = 1000000;
    long long a = 0, b = 0, c = 0;
    for (long long i = 1; i <= n; i++) a++;          // n rounds
    for (long long i = 1; i <= n; i *= 2) b++;       // log n rounds
    for (long long i = 1; i * i <= n; i++) c++;      // sqrt n rounds
    cout << a << " " << b << " " << c << "\n";
    return 0;
}

6. When the inner loop depends on i: add the series

If the inner loop's count changes with i, don't just multiply the two loop counts. Write how many times the inner loop runs for i = 1, 2, 3, …, then add them up.

Inner loop runsTotalBig-O
i times (j <= i)1 + 2 + … + n = n(n+1)/2O(n²)
i² times (j <= i * i)1² + 2² + … + n² ≈ n³/3O(n³)
i times, while i doubles (1, 2, 4, …)1 + 2 + 4 + … + n/2 < nO(n)
log i times (j *= 2 up to i)log 1 + log 2 + … + log n = log(n!) ≤ n log nO(n log n)

The same idea works for a while loop that adds a growing amount: if s becomes 1, 3, 6, 10, … (1 + 2 + … + k), it passes n after about √(2n) steps, so the loop is O(√n).

7. From the limits to the approach

The input limits tell you which complexity is allowed. Read them before you choose an approach.

Largest nComplexity that fits
n ≤ 10O(n!)
n ≤ 20O(2ⁿ)

n ≤ 10^6O(n log n) or O(n)
n ≤ 10^8O(n), with simple steps
n ≥ 10^9O(√n), O(log n) or O(1)

With several test cases, multiply: 10^5 tests × O(n) with n = 10^5 is 10^10 steps, which is far too slow.

8. Space complexity

Space complexity measures the extra memory a program uses as n grows.

  • A few variables: O(1). An array of n numbers: O(n). An n × n grid: O(n²).
  • Sizes: int 4 bytes, long long and double 8 bytes, char and bool 1 byte.
  • 256 MB holds about 6.4 × 10^7 ints or 3.2 × 10^7 long longs. An int array of 10^6 is only 4 MB.
  • A 10^5 × 10^5 grid would need 10^10 cells, far too much. That limit tells you to find another way.

9. Best, worst and average case

Searching an array for a value can finish at the first element (best case) or check all n (worst case). We usually quote the worst case, because the judge will try inputs that make your program slowest.

10. Common mistakes

  1. Looking only at the code, not the limits. O(n²) is fine for n = 1,000 and hopeless for n = 10^5.
  2. Forgetting the number of test cases. Total work = tests × work per test.
  3. Thinking O(2n) is slower than O(n). Constants are dropped; both are O(n).
  4. Calling every nested loop O(n²). If the inner loop halves, runs a fixed number of times, or its variable never resets, it is smaller.
  5. Multiplying the loop counts when the inner loop depends on i. Write the series and add it up instead.
  6. Declaring huge arrays inside main. Large arrays belong outside main (global), where there is more room.
