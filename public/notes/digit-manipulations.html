1. The template

Every digit problem uses the same loop. Steps 1 and 3 never change; only step 2 does.

while (n > 0) {
    int digit = n % 10;     // step 1: access the last digit
    // step 2: process the digit (the only part that changes)
    n = n / 10;             // step 3: drop the last digit
}
  • n % 10 gives the last digit: 1234 % 10 = 4.
  • n / 10 drops the last digit: 1234 / 10 = 123.
  • The loop runs once per digit, so it is O(number of digits) = O(log₁₀ n). Even a 10^18 number has only 19 digits.

Why log n: each n = n / 10 divides n by 10, the same idea as halving, with base 10. After k steps n has become n / 10^k, which reaches 0 when k ≈ log₁₀ n. (For a fixed 32-bit int there are at most 10 digits, so some books write O(1). Say O(log n) unless the question says n is bounded.)

#include <iostream>
using namespace std;

int main() {
    int n = 4721;
    int cnt = 0, sum = 0, prod = 1, rev = 0, sevens = 0, bits = 0, p = 1;
    for (int t = n; t > 0; t /= 10) {
        int d = t % 10;
        cnt++; sum += d; prod *= d; rev = rev * 10 + d;
        if (d == 7) sevens++;
    }
    for (int t = n; t > 0; t /= 2) bits++;            // base 2
    for (int i = 1; i < cnt; i++) p *= 10;             // 10^(digits - 1), no pow()
    cout << n % 10 << " " << n / 10 << " " << cnt << " " << sum << " " << prod << " " << rev << "\n";
    cout << n / p << " " << (n / 100) % 10 << " " << n * 10 + 5 << " " << sevens << " " << bits << " " << 1 + (n - 1) % 9 << "\n";
    return 0;
}

3. The loop destroys the number: work on a copy

After the loop, n is 0. If you need the original value later (to compare with, divide by, or return), save it first.

int original = n;      // save BEFORE the loop
int temp = n;          // and loop on temp, not on n

4. Direction: the template reads from the back

4729 is read as 9 → 2 → 7 → 4. That doesn't matter for a sum, count, product, maximum or minimum. When the problem needs the digits from the front, use one of these:

MethodHowWatch out
Convert to a stringstring s = to_string(n); then s[i] - '0'Simplest and least error-prone. Uses O(digits) extra space.
Store the digits in a vectorpush_back each digit, then loop backwardsAlso gives access to any digit.
Reverse the number firstReverse n, then run the template on itTrailing zeros are lost (1200 → 21), and it can overflow.
Divisor methoddiv = 10^(digits − 1); digit = n / div; then n %= div, div /= 10Build div with an integer loop, not pow().
 
#include <iostream>
#include <string>
using namespace std;

int main() {
    int n = 4729;

    int t = n;                                        // the template: back to front
    while (t > 0) { cout << t % 10 << " "; t /= 10; }
    cout << "\n";

    string s = to_string(n);                          // string: front to back
    for (int i = 0; i < (int)s.size(); i++) cout << s[i] - '0' << " ";
    cout << "\n";

    int div = 1;                                      // divisor method: front to back
    while (n / div >= 10) div *= 10;                  // div = 1000
    t = n;
    while (div > 0) {
        cout << t / div << " ";                       // access from the front
        t %= div;                                     // drop from the front
        div /= 10;
    }
    cout << "\n";
    return 0;
}

5. Negative numbers

  • In C++, % takes the sign of the left number and / cuts toward zero: -123 % 10 is −3 (not 7, as in Python) and -123 / 10 is −12.
  • while (n > 0) never runs for a negative n. Use while (n != 0) if negatives must be processed.
  • The cleanest fix is usually to handle the sign separately: bool neg = n < 0; n = abs(n);
  • Careful: abs(INT_MIN) overflows, because there is no +2,147,483,648 in an int. Convert first: long long x = llabs((long long)n);

6. Overflow

INT_MAX is 2,147,483,647 (10 digits). These can overflow even when the input fits:

  • Reversing: 1999999999 reversed is 9999999991, larger than INT_MAX.
  • Products, powers and factorials of digits (Armstrong, Strong numbers), and building a number with res * 10 + digit.

Fix: use long long for the result. When 64-bit isn't allowed (as in LeetCode 7), check before multiplying:

if (rev > INT_MAX / 10 || (rev == INT_MAX / 10 && digit > 7)) return 0;   // would overflow
rev = rev * 10 + digit;

7. Zeros

  • n = 0: while (n > 0) never runs, so “count digits” gives 0 instead of 1. Special-case it, or use a do { … } while (n > 0); loop, which runs at least once.
  • A digit can be 0. If step 2 does num / digit or num % digit, guard it: if (digit != 0 && num % digit == 0). Dividing by zero is undefined behaviour: the program may crash or give garbage.
  • Leading zeros don't exist in numbers: 007 is just 7. Trailing zeros vanish when reversed (120 → 21), which matters for palindromes: 10 is not a palindrome, so handle n % 10 == 0 early.
  • In string or array input (“007”, or a result like [0, 1, 2]), strip the leading zeros but keep a single “0”.

8. Math shortcuts

Some questions have a formula that skips the loop, or must avoid building the number at all.

  • Number of digits of n in base b is ⌊log_b n⌋ + 1 (for n ≥ 1). Handy for reasoning; in code, the integer loop is safer.
  • n % 9 equals (sum of digits) % 9. That makes the digital root a 9-cycle: 1 + (n − 1) % 9 for n ≥ 1. The same works for 3.
  • Divisible by 11 exactly when the alternating digit sum is divisible by 11: 1342 → 1 − 3 + 4 − 2 = 0, and 1342 = 11 × 122.
  • Trailing zeros of n! = n/5 + n/25 + n/125 + …. Each zero needs a 2 × 5, and 5s are rarer, so count factors of 5. Never compute n! itself: it overflows.
  • Other bases: the same loop with % b and / b gives the digits in base b (binary uses b = 2).
  • Numbers too big for any type (digits given as an array or string) are handled digit by digit with a carry, like schoolbook addition.

9. More tips

  • Avoid floating point for digit maths. log10(n) + 1 fails for 0 and negatives and can be off near powers of 10. pow(10, k) returns a double, and converting it to int can give 99 instead of 100 on some compilers. Use integer loops (div *= 10).
  • Character ↔ digit: int d = s[i] - '0'; turns '7' into 7, and char c = '0' + d; turns 7 into '7'.
  • String conversion is easy but costs O(log n) extra space, and is often not allowed. Say so when a question asks for O(1) space.
  • Read the constraints. A range like −2^31 ≤ x ≤ 2^31 − 1 tells you whether negatives, 0 or overflow are possible.
