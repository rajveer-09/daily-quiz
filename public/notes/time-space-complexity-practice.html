For each piece of code, find the time complexity in Big-O before opening the answer. Count how many times count++ runs.

1. A big fixed loop

int count = 0;
for (int i = 1; i <= 1000000; i++)
    count++;
Hint

Does the number of rounds change when n changes?

Answer

O(1). The loop runs 1,000,000 times whatever n is. A big number doesn't make a loop slow in Big-O terms; what matters is whether the count grows with n.

2. Inner loop up to i

int count = 0;
for (int i = 1; i <= n; i++)
    for (int j = 1; j <= i; j++)
        count++;
Hint

The inner loop depends on i. Write how many times it runs for i = 1, 2, 3, …, n and add them.

Answer

O(n²).

i = 1  =>  1
i = 2  =>  2
  ...
i = n  =>  n
-----------------------------------------
1 + 2 + ... + n = n(n+1)/2 = n²/2 + n/2  ->  O(n²)

3. i doubles, inner loop up to i

int count = 0;
for (int i = 1; i < n; i = i * 2)
    for (int j = 0; j < i; j++)
        count++;
Hint

The outer loop runs only log n times, but the inner loop runs i times. List the values of i and add them.

Answer

O(n), not O(n log n).

i = 1    =>  1
i = 2    =>  2
i = 4    =>  4
  ...
i = n/2  =>  n/2   (last value below n)
-----------------------------------------
1 + 2 + 4 + ... + n/2  <  n   (each term is more than all earlier ones put together)  ->  O(n)

Multiplying the loop counts (log n × n) would overestimate it: write the series instead.

4. A sum that grows

int i = 1, s = 1;
while (s <= n) {
    i++;
    s = s + i;
}
Hint

Write the value of s after each step. Which formula is it? When does it pass n?

Answer

O(√n).

after step 1:  s = 1
after step 2:  s = 1 + 2     = 3
after step 3:  s = 1 + 2 + 3 = 6
  ...
after step k:  s = 1 + 2 + ... + k = k(k+1)/2
-----------------------------------------
stop when s > n:  k²/2 ≈ n  =>  k ≈ √(2n)  ->  O(√n)

5. The variable that never resets

int count = 0, j = 0;
for (int i = 0; i < n; i++)
    while (j < n) {
        j++;
        count++;
    }
Hint

Where is j set to 0? What is j when i becomes 1?

Answer

O(n), not O(n²).

j is set to 0 once, OUTSIDE both loops. It never resets.

i = 0    =>  while runs n times   (j goes 0 → n)
i = 1    =>  while runs 0 times   (j is already n)
  ...
i = n-1  =>  0
-----------------------------------------
inner work = n,  outer loop = n,  total = 2n  ->  O(n)

The code looks nested, but j only moves from 0 to n once in total.

6. Will it pass?

A problem gives up to n = 2 × 10^5 numbers and a 1-second limit. Your idea checks every pair of numbers with two nested loops. Will it pass? If not, what complexity should you aim for?

Hint

How many pairs are there? Compare that with about 10^8 operations per second.

Answer

No. Checking every pair is O(n²): about (2 × 10^5)² / 2 = 2 × 10^10 operations, around 200 times over the budget. With n = 2 × 10^5, aim for O(n log n) (about 3.5 × 10^6 steps) or O(n), for example by sorting first.
