Analysing time complexity: 6 steps

  1. Decide what n is. The size of the input: how many numbers, the value of the number, or the length of the string. If there are two sizes (n and m), keep both.
  2. Find the line that runs most often, usually the innermost statement. The question becomes: how many times does it run?
  3. Count each loop's rounds, from the inside out, by looking at how its variable changes:
    The loop variable…Rounds
    goes up or down by 1 (or any fixed step) up to nn (or n / step) → O(n)
    is multiplied or divided by a constant (×2, ×3, ÷2)log n
    is squared each round (i = i * i)log log n
    stops at i * i <= n√n
    runs a fixed number of times (26, 1000, 10^6)a constant → O(1)
  4. Combine the loops.
    • One after another: add (n + m).
    • One inside another, when the inner count doesn't depend on the outer variable: multiply (n × log n).
    • When the inner count depends on the outer variable: write the inner count for i = 1, 2, 3, … and add the series (see Notes, section 6).
  5. Check for traps.
    • Does the inner variable reset? If it is set once outside the loops, it only moves forward once in total, which can make nested code linear.
    • Does the loop break early? Use the worst case: assume the break comes as late as possible.
    • Hidden costs: a function call inside a loop costs its own complexity each time. sort is O(n log n); searching a whole vector is O(n); s = s + c copies the whole string (O(length)), while s += c doesn't.
  6. Simplify. Keep the fastest-growing term and drop the constants: 3n² + 5n + 7 → O(n²); 5n, n/2 and 2n are all O(n).

Worked example: time

for (int i = 0; i < n; i++) sum += a[i];               // part A

for (int i = 1; i <= n; i++)                            // part B
    for (int j = 1; j < n; j *= 2) cnt++;

for (int i = 0; i < n; i++)                             // part C
    for (int j = i; j < n; j++) cnt++;

1. n is the length of the array.

2–3. Part A: one loop, +1 each round → n.

Part B: the inner j doubles → log n rounds, the same for every i. Nested and independent, so multiply → n log n.

Part C: the inner loop starts at i, so it depends on the outer variable. Write the series: n + (n − 1) + … + 1 = n(n + 1)/2.

4. Combine: A, B and C run one after another, so add: n + n log n + n(n + 1)/2.

5. Traps: no early break, no shared variable, no hidden calls.

6. Simplify: the biggest term is n²/2 → O(n²).

Analysing space complexity: 5 steps

  1. Count only the extra memory your code creates. The input itself is usually not counted (this is called auxiliary space). Say so if a question counts the input too.
  2. List everything you create and write its size in terms of n: single variables, arrays, vectors, strings, 2-D grids.
  3. Separate reused memory from growing memory. A variable declared inside a loop is reused every round, so it counts once: O(1). A vector you push_back into in a loop grows to the number of rounds.
  4. Recursion (later topics): every call that is still waiting sits on the call stack, so the space is the deepest chain of calls × the memory of one call.
  5. Simplify, then check bytes. Keep the biggest term (O(1), O(n), O(n·m), O(n²)). Then multiply by the size of one element and compare with the limit:
    TypeBytesFits in 256 MB
    char, bool1about 2.5 × 10^8
    int4about 6.4 × 10^7
    long long, double8about 3.2 × 10^7

Worked example: space

int n;
cin >> n;
vector<int> a(n);                                   // n ints
int freq[26] = {0};                                 // 26 ints
vector<vector<int>> grid(n, vector<int>(n));      // n × n ints
long long sum = 0;
for (int i = 0; i < n; i++) {
    int x = a[i];                                   // reused every round
    sum += x;
}

1–2. List: a is n ints → O(n). freq is always 26 → O(1). grid is n × n → O(n²). sum, i and x are single variables → O(1).

3. Reused or growing: x is created inside the loop but reused, so it stays O(1).

5. Simplify: the biggest term is the grid → O(n²).

Check bytes: for n = 10^4 the grid has 10^8 ints = 400 MB, over a 256 MB limit. For n = 5,000 it is 10^8 bytes = 100 MB, which fits.

Before you code: will it fit?

  1. Read the limits: the largest n, and the number of test cases T.
  2. Budget: about 10^8 simple operations per second, in total across all test cases.
  3. Find the complexity allowed with the limits table in the notes (n ≤ 5,000 → O(n²), n ≤ 10^6 → O(n log n), and so on).
  4. Work out the complexity of your simplest correct idea with the 6 steps above. If it fits, code it.
  5. If it doesn't fit, remove the repeated work: stop early (√n), reuse earlier results, sort first, or use a formula. Then check memory with the 5 steps.

Example: count the divisors of n ≤ 10^12. Trying every d from 1 to n is O(n) = 10^12 steps, far too slow. Divisors come in pairs d and n / d, and the smaller one is at most √n, so loop only while d * d <= n: O(√n) = 10^6 steps, with O(1) memory.

#include <iostream>
using namespace std;

int main() {
    long long n;
    cin >> n;
    long long cnt = 0;
    for (long long d = 1; d * d <= n; d++) {
        if (n % d == 0) {
            cnt++;                       // d itself
            if (d != n / d) cnt++;       // its pair n / d, unless it is the same number
        }
    }
    cout << cnt << "\n";
    return 0;
}
