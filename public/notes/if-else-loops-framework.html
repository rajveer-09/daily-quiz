Before any question

  1. Read the input format and the exact output words. Yes is not YES.
  2. Check the limits. They decide the types (int or long long) and how fast the code must be.
  3. Solve 2 small examples by hand.
  4. Only then write code. Then find which pattern below the question matches.

Conditions (if / else)

1. Comparing a few values: largest, smallest, middle

You will see

  • The largest or smallest of 3 or 4 numbers, or both together.
  • The second largest or the middle value.
  • Picking the cheaper or better of two options.

Keep in mind

  • Values can be negative or equal. Never start the answer at 0.
  • max(a, b) and min(a, b) exist and can be nested: max(a, max(b, c)).
  • If the options are costs, turn each option into one number (its total) first, then compare.

How to think: the champion method

Assume the first value is the answer. Look at each other value; if it beats the current answer, it becomes the new answer. The middle of 3 values is total − largest − smallest.

int best = a;                // the champion starts as a real input value
if (b > best) best = b;      // challenge it with each other value
if (c > best) best = c;      // (flip > to < for the smallest)

2. Divisibility labels

You will see

  • Even or odd; positive, negative or zero.
  • A word if N is divisible by one number, another word for a second number, a combined word if both.
  • Leap-year rules: divisible by 4, but not by 100, unless by 400.

Keep in mind

  • “Divisible by k” is n % k == 0.
  • “Divisible by both p and q”: check both with &&, or check their LCM (both 4 and 6 means divisible by 12).
  • One input can match more than one rule. If the “both” case is checked last, it is never reached.

How to think

List the cases, then ask: can one input fit two cases at once? If yes, the overlap (the most specific case) goes first, then the single cases, then the else. Test with an input that falls in the overlap.

if (n % 3 == 0 && n % 5 == 0) cout << "FizzBuzz";   // most specific first
else if (n % 3 == 0)          cout << "Fizz";
else if (n % 5 == 0)          cout << "Buzz";
else                          cout << n;            // none matched

3. Validate first, then classify

You will see

  • Can these sides or angles form a shape? If yes, what type is it?
  • Is this date, time, mark or age valid? If yes, which category?

Keep in mind

  • There are two questions inside: “Is it possible?” and “What kind is it?”
  • The validity rule is usually in the question, or a known fact (the angles of a triangle add up to 180).
  • “How many are equal” is easiest by counting equal pairs.

How to think

  1. Write the “impossible” conditions first. If any is true, print the invalid message and stop.
  2. Only then classify. The data is now valid, so the classification stays simple.
  3. For “all same / two same / all different”, count equal pairs: 3 pairs → all same, 1 → two same, 0 → all different.
if (/* impossible input */) {
    cout << "Invalid";
    return 0;                                     // stop here
}
int same = (x == y) + (y == z) + (x == z);        // true counts as 1
if (same == 3)      cout << "All same";
else if (same == 1) cout << "Two same";
else                cout << "All different";

4. Rule ladders: eligibility, grading, pricing

You will see

  • A list of rules with “if … otherwise if … otherwise”, taking 3–4 inputs and printing a decision.
  • A rule with a sub-rule inside it: “otherwise, if X then A, else B”.
  • Ranges such as “between 600 and 749 inclusive”.

Keep in mind

  • Follow the rules in the exact order given. Each “otherwise” is an else; a sub-rule is an if inside that branch.
  • When you reach an else if, everything above it is already false, so you rarely need to re-check a range's lower bound.
  • “Inclusive” means the end values count: x >= 600 && x <= 749.
  • Copy the output strings exactly, including brackets and spaces.

How to think

Draw the rules as a tree. Every leaf is one output. Make one test input per leaf, plus the boundary values (exactly 600, exactly 749, exactly 750).

rule 1 true? ── yes ─> A
   │ no
rule 2 true? ── yes ─> B
   │ no
rule 3 true? ── yes ─> sub-rule true? ── yes ─> C
   │ no                     │ no
   └──────> E               └──────> D
if (/* rule 1 */)       cout << "A";
else if (/* rule 2 */)  cout << "B";
else if (/* rule 3 */) {
    if (/* sub-rule */) cout << "C";
    else                cout << "D";
}
else                    cout << "E";

5. Formula and ratio checks

You will see

  • Does a ratio equal something (width : height = p : q)?
  • Does a formula cross a limit (a percentage, an average, a speed)?
  • Does any of several results (sum, difference, product) equal a value?
  • Can a number be split into parts with a property (two even parts, equal teams)?

Keep in mind

  • Avoid division. Integer division cuts the fraction and double brings tiny errors. Multiply both sides instead.
  • Watch for unit changes (cm → m means ÷ 100, so a square means ÷ 10,000).
  • For “split into parts” questions, try the smallest inputs by hand (1, 2, 3, 4). Small cases often break a rule that looks right.

How to think

Write the check as maths, then move every divisor to the other side (for positive b and d).

You wantWrite in code
a / b == ka == k * b
a / b ≥ c / da * d >= c * b
x : y equals p : qx * q == y * p
marks / total ≥ 40%marks * 100 >= 40 * total

6. Character and string checks

You will see

  • A short string: do characters repeat, how often each appears, are there exactly two kinds?
  • Classify a character: vowel, digit, uppercase.

Keep in mind

  • s[0] is the first character; s.size() is the length.
  • Characters compare like numbers: c >= 'a' && c <= 'z'.
  • Counting how often each character appears often turns the question into a simple check on the counts.

How to think

Ask “what would I count by hand?”, count it in code, then check the counts.

string s;
cin >> s;
int cnt = 0;
for (int i = 0; i < (int)s.size(); i++)
    if (s[i] == s[0]) cnt++;           // how many equal the first character?

Loops

1. Printing ranges and sequences

You will see

  • Print 1 to N, or N down to 1.
  • Print the first K numbers of a pattern (multiples, odd numbers, 3k + 1…).
  • Print the numbers of a range with a step.

Keep in mind

  • Every loop answers three questions: start, stop, step.
  • The values from a to b are b − a + 1 numbers.
  • < versus <= is the most common bug. Check the first value printed, the last value printed, and the count.

How to think

Write the first 4 terms next to their position and find the formula for term i.

i1234
term471013

The gap is 3, so term = 3i + something. At i = 1: 3 + 1 = 4, so term = 3i + 1.

for (int i = 1; i <= N; i++) cout << i << " ";           // up
for (int i = N; i >= 1; i--) cout << i << " ";           // down
for (int i = 1; i <= K; i++) cout << 3 * i + 1 << " ";   // first K terms by formula

2. Tables and formatted output

You will see

  • A multiplication table, or lines in a fixed format such as 7 x 3 = 21.

Keep in mind

  • Copy the spaces and symbols of the output format exactly.
  • One loop, one line per round, "\n" at the end of each line.
for (int i = 1; i <= 10; i++)
    cout << n << " x " << i << " = " << n * i << "\n";

3. Picking numbers without if: jump, don't filter

You will see

  • Print only the even numbers, odd numbers or multiples of k up to N, sometimes “without using if-else”.

Keep in mind

  • Filter: visit every number and test it with if.
  • Jump: start on the first wanted number and step by the gap. No if needed, and fewer steps.
  • Decide the first wanted value carefully: does the range start at 0 or 1?
for (int i = START; i <= N; i += GAP) cout << i << " ";   // jump, no if

4. Sums and products (accumulators)

You will see

  • The sum or product of 1 to N, or of a pattern; powers such as 2ⁿ.

Keep in mind

  • Start a sum at 0 and a product at 1. A product that starts at 0 stays 0.
  • Estimate the size first. Products explode: 1 × 2 × … × 12 = 479,001,600 fits in int, but 1 × 2 × … × 13 = 6,227,020,800 does not.
  • int holds about 2.1 × 10⁹ and long long about 9.2 × 10¹⁸. If unsure, use long long.

How to think

“What is the value of nothing yet?” That is the starting value. Each round then adds or multiplies one more term.

long long sum = 0, prod = 1;
for (int i = 1; i <= N; i++) {
    sum += i;
    prod *= i;
}

5. Divisor questions

You will see

  • Print all divisors of N, count them, or add them up.
  • Decide whether N has a property based on its divisors (prime, perfect number).

Keep in mind

  • d divides n when n % d == 0.
  • Divisors come in pairs: for 36, (1, 36), (2, 18), (3, 12), (4, 9), (6, 6). One of each pair is ≤ √n, so “does any divisor exist in 2…n−1?” only needs d * d <= n.
  • 0 and 1 often behave differently. Check what the problem expects for them.

How to think

Do I need every divisor, or only to know whether one exists? Every divisor → loop d from 1 to n. Whether one exists → loop up to √n and break at the first one found.

for (int d = 1; d <= n; d++)               // every divisor
    if (n % d == 0) cout << d << " ";

bool found = false;                         // does one exist?
for (int d = 2; d * d <= n; d++)
    if (n % d == 0) { found = true; break; }

6. Flags: “is there any…?” and “are all…?”

You will see

  • Does N contain a certain digit? Are all digits odd? Is there a divisor in a range?

Keep in mind

  • “Is there any?” Assume false; set it to true when you find one.
  • “Are all?” Assume true; set it to false at the first counterexample.
  • Either way, break as soon as the answer is known.
bool ok = true;                              // false for "is there any?"
for (/* each item */) {
    if (/* counterexample */) { ok = false; break; }
}
cout << (ok ? "Yes" : "No");

7. Digits of a number

You will see

  • Count digits, add them up, reverse a number, check digits one by one.

Keep in mind

  • n % 10 is the last digit; n / 10 removes it.
  • Work on a copy if you need the original number later.
  • 0 has 1 digit, but while (t > 0) never runs for it. Handle it separately.
  • For negative numbers, take abs() first.
