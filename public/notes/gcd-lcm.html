1. Definitions

GCD (greatest common divisor, also called HCF): the largest number that divides both a and b with no remainder.

Divisors of 12 are 1, 2, 3, 4, 6, 12 and of 18 are 1, 2, 3, 6, 9, 18. The largest common one is 6, so gcd(12, 18) = 6.

LCM (least common multiple): the smallest positive number that both a and b divide.

Multiples of 4 are 4, 8, 12, 16 and of 6 are 6, 12, 18. The first common one is 12, so lcm(4, 6) = 12.

2. The prime-factor view

Write both numbers as prime powers. The GCD takes the smaller exponent of each prime; the LCM takes the larger. With 12 = 2² × 3 and 18 = 2 × 3²:

QuantityRuleResult
gcd(12, 18)smaller exponents: 2¹ × 3¹6
lcm(12, 18)larger exponents: 2² × 3²36

3. The key identity

gcd(a, b) × lcm(a, b) = a × b. Check: 6 × 36 = 216 = 12 × 18.

So lcm(a, b) = a / gcd(a, b) × b. Dividing first keeps the numbers small.

4. Euclid's algorithm

Keep replacing (a, b) with (b, a % b) until b becomes 0. Then a is the GCD: gcd(a, b) = gcd(b, a % b) and gcd(a, 0) = a.

StepDivisionNext pair
148 = 2 × 18 + 12gcd(18, 12)
218 = 1 × 12 + 6gcd(12, 6)
312 = 2 × 6 + 0gcd(6, 0) = 6

It takes O(log min(a, b)) steps, so it is instant even for numbers up to 10^18.

5. Facts you will use

FactWhy it matters
gcd(a, 0) = a, and gcd(0, 0) = 00 is the safe starting value for a GCD over an array
gcd(a, b) = gcd(a, b − a)Subtracting never changes the GCD, so the GCD of an array equals the GCD of its differences
gcd(a, b, c) = gcd(gcd(a, b), c)Fold a loop over the array; the same works for LCM
gcd(k·a, k·b) = k · gcd(a, b)Take a common factor out to simplify
If gcd(a, b) = 1, lcm(a, b) = a × bThe numbers are coprime, and the LCM grows fast
ax + by = c has a solution only if gcd(a, b) divides cBézout's identity: equation and water-jug problems
gcd ≤ min(a, b), and lcm ≥ max(a, b)Quick bounds to sanity-check an answer

6. C++ code

In contests use the built-ins from <numeric> (C++17): gcd(a, b) and lcm(a, b). They work on absolute values and accept mixed types. On older compilers, GCC has __gcd(a, b), with both values of the same type. Write your own only when you need it.

#include <bits/stdc++.h>
using namespace std;

long long gcdRec(long long a, long long b) {          // recursive Euclid
    return b == 0 ? a : gcdRec(b, a % b);
}

long long gcdIter(long long a, long long b) {         // iterative Euclid
    while (b != 0) {
        long long r = a % b;
        a = b;
        b = r;
    }
    return a;
}

long long lcmSafe(long long a, long long b) {
    if (a == 0 || b == 0) return 0;
    return a / gcd(a, b) * b;                         // divide FIRST, then multiply
}

int main() {
    cout << gcd(12, 18) << " " << lcm(12, 18) << "\n";       // built-ins
    cout << gcdRec(48, 18) << " " << gcdIter(48, 18) << "\n";
    cout << lcmSafe(4, 6) << "\n";

    vector<long long> v = {12, 18, 30};
    long long g = 0, l = 1;                          // GCD starts at 0, LCM at 1
    for (long long x : v) { g = gcd(g, x); l = lcm(l, x); }
    cout << g << " " << l << "\n";

    cout << gcd(0, 5) << " " << gcd(-12, 18) << "\n";       // gcd(0, x) = x; signs are ignored
    return 0;
}

7. Common mistakes

  1. Overflow in the LCM. a * b / gcd(a, b) can overflow before the division. Always write a / gcd(a, b) * b. An LCM folded over an array can still pass 9.2 × 10^18, so stop or cap it at the limit you care about.
  2. int instead of long long. int overflows above about 2 × 10^9, and products and LCMs get big fast.
  3. Wrong starting value. Start a GCD loop at 0 and an LCM loop at 1. A GCD loop that starts at 1 always gives 1.
  4. Zero. gcd(0, 0) = 0, so check before dividing by a GCD.
  5. Negative numbers in your own GCD. % keeps the sign of the left number, so a hand-written Euclid can return −6 for (−12, 18). Use the built-in gcd, or take llabs first.
  6. LCM under a modulus. Taking % MOD step by step gives wrong answers, because the LCM divides by the GCD. Use the larger exponent of each prime instead.
  7. Compiler version. gcd and lcm need C++17 (-std=c++17). __gcd needs both values of the same type.
