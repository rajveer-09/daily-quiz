1. The problem

Compute aᵇ, usually mod m, when b can be as large as 10^18.

  • The plain loop for (i = 0; i < b; i++) r *= a; takes b steps. For b = 10^18 that would run for centuries.
  • aᵇ itself is astronomically large (2^100 has 31 digits), so it never fits in a long long. Problems ask for it mod some m, often 10⁹ + 7.

Fast exponentiation (also called binary exponentiation or exponentiation by squaring) needs only about log₂ b steps: around 60 for b = 10^18.

2. The idea: square, don't multiply one at a time

  • If b is even: aᵇ = (a^(b/2))², so one answer for half the exponent, squared.
  • If b is odd: aᵇ = a × a^(b−1), and b − 1 is even.

Each step halves the exponent: 3¹³ needs 3⁶, which needs 3³, which needs 3¹, then 3⁰ = 1. Four halvings instead of 13 multiplications.

3. The binary view

Write b in binary. 13 = 1101₂ = 8 + 4 + 1, so

3¹³ = 3⁸ × 3⁴ × 3¹

The powers 3¹, 3², 3⁴, 3⁸ come from squaring again and again. Multiply into the answer only those whose bit of b is 1. That is the iterative algorithm.

411243 × 6561 = 1594323(not needed)

After round 4, b becomes 0 and the loop stops: 3¹³ = 1594323.

4. Code

#include <bits/stdc++.h>
using namespace std;

long long powRec(long long a, long long b) {       // recursive; no modulus, small results only
    if (b == 0) return 1;
    long long half = powRec(a, b / 2);
    return b % 2 == 0 ? half * half : half * half * a;
}

long long modPow(long long a, long long b, long long m) {   // iterative, a^b mod m
    long long r = 1 % m;
    a %= m;
    if (a < 0) a += m;
    while (b > 0) {
        if (b & 1) r = r * a % m;      // this bit of b is 1: multiply it in
        a = a * a % m;                 // a, a^2, a^4, a^8, ...
        b >>= 1;                       // move to the next bit
    }
    return r;
}

int main() {
    cout << powRec(3, 13) << "\n";
    cout << modPow(2, 10, 1000) << "\n";                          // 1024 % 1000
    cout << modPow(2, 1000000000000000000LL, 1000000007) << "\n";  // 2^(10^18) mod 1e9+7
    return 0;
}

  • b & 1 is the last bit of b (1 when b is odd), and b >>= 1 halves b, dropping that bit.
  • Time: O(log b). Space: O(1) for the loop; the recursive version uses O(log b) for its calls.

5. Working modulo m

  • (x × y) % m = ((x % m) × (y % m)) % m. So you can take % m after every multiplication, and the numbers stay below m.
  • Reduce the base first: a %= m. A base like 10^18 would otherwise overflow on the first squaring.
  • Overflow limit: r * a is below m², so it fits in a long long (about 9.2 × 10^18) only while m is at most about 3 × 10^9. For 10⁹ + 7 that is fine. For bigger m, use __int128 (on 64-bit compilers) for the multiplication.
  • Never use pow() from <cmath> here: it works with double, loses digits on big numbers, and can't take a modulus.

6. Modular inverse (Fermat)

Division doesn't work under a modulus: (a / b) % m is not (a % m) / (b % m). Instead, multiply by the inverse of b: the number b⁻¹ with b × b⁻¹ ≡ 1 (mod m).

When m is prime and b is not a multiple of m, Fermat's little theorem gives

b⁻¹ ≡ b^(m−2)  (mod m)

So the inverse is just modPow(b, m - 2, m). For example, the inverse of 3 mod 10⁹ + 7 is 333333336, because 3 × 333333336 = 1000000008 ≡ 1. This is how nCr mod p and averages mod p are computed.

Fermat also shrinks huge exponents: for prime p and a not a multiple of p, a^e ≡ a^(e mod (p − 1)) (mod p).

7. Beyond numbers: matrix power

The same squaring works for anything you can multiply, such as matrices. Fibonacci numbers satisfy

[ F(n+1)  F(n)   ]   =   [ 1  1 ] ⁿ
[ F(n)    F(n−1) ]       [ 1  0 ]

so F(n) for n = 10^18 takes about 60 matrix squarings. Practice problem 6 uses this.

8. Common mistakes

  1. Forgetting a %= m before the loop. The first a * a overflows.
  2. Using int for r or a. r * a needs long long even when m fits in an int.
  3. Taking the mod only at the end. The numbers overflow long before; take it after every multiplication.
  4. b = 0 and m = 1. a⁰ = 1, but 1 % 1 = 0, which is why the code starts with r = 1 % m.
  5. Negative base. % can return a negative number in C++; add m once after reducing.
  6. Inverse with a non-prime m, or with b a multiple of m. Fermat needs a prime m and b not divisible by it.
